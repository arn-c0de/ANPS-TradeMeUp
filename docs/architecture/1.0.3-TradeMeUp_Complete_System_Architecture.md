## Executive Summary

### What Is TradeMeUp?

TradeMeUp is a **production-grade AI trading system** that implements the **News vs Market Consistency Framework**. It is NOT a naive "news → price prediction" bot, but a sophisticated multi-agent system that:

1. **Models two parallel worlds**:
   - **Expected World (E)**: What prices should look like based on news, sentiment, and macro data
   - **Observed World (R)**: What the market actually does

2. **Detects divergence** (Δ = E - R) to identify trading opportunities and risks

3. **Operates as a human-supervised decision support system**, not a fully autonomous trader

### Core Innovation

The system recognizes that **markets are reflexive and non-stationary**. Instead of trying to predict prices directly, it:

- Maintains multiple scenario hypotheses
- Detects market regime transitions
- Quantifies model uncertainty
- Accounts for transaction costs and market impact
- Provides explainable predictions with confidence calibration

## Theoretical Framework

### 1. Core Concept: Expectation vs Reality

```
┌─────────────────────────────────────────────────────┐
│                                                     │
│  Expected World (E)          Observed World (R)    │
│  ─────────────────          ─────────────────      │
│                                                     │
│  • News analysis              • Actual prices      │
│  • Sentiment models           • Volume patterns    │
│  • Macro models               • Volatility         │
│  • Analyst consensus          • Order flow         │
│  • Historical patterns        • Liquidity          │
│                                                     │
│             Δ = E - R (Divergence)                  │
│                    ↓                                │
│         Risk Score + Opportunity Signal             │
│                                                     │
└─────────────────────────────────────────────────────┘
```

**Key Insight**: Divergence (Δ) doesn't mean the market is wrong. It means:
- Uncertainty exists
- Regime mismatch possible
- Friction in price discovery
- Potential opportunity (with risk)

### 2. Why This Approach Works

**Market Reality:**
- Humans trade by heuristics, patterns, and speculation
- AI can do the same, but faster, with more data, and without emotional bias
- If humans can profit under uncertainty, AI can in principle as well

**Critical Constraints:**
- Markets are reflexive (predictions influence outcomes)
- Relationships are non-stationary (what worked yesterday may fail today)
- Transaction costs can eliminate all alpha
- Model degradation is inevitable

**Solution:**
- Multiple hypotheses instead of single predictions
- Regime-aware strategies
- Continuous model monitoring and adaptation
- Human oversight for critical decisions

### 3. Key Principles

#### 3.1 No Single Predictions
```
❌ "Price will be $150 in 5 days"
✅ Scenario A (p=0.4): $145-$155
   Scenario B (p=0.35): $135-$145  
   Scenario C (p=0.25): $155-$165
```

#### 3.2 Regime Dependency
```
Regime ∈ {
  Trend (Bull/Bear/Sideways),
  Volatility (Low/Medium/High),
  Risk Appetite (Risk-On/Risk-Off),
  Liquidity (Normal/Stressed),
  Transition (Regime-Shift)
}
```

All signals and strategies are **conditioned on regime**.

#### 3.3 Risk-First Mentality
```
Risk_Score = f(
  model_uncertainty,
  divergence_magnitude,
  volatility_regime,
  liquidity_stress,
  regime_confidence,
  transaction_cost_ratio,
  market_impact_estimate,
  correlation_breakdown
)
```

**High risk score → Reduce exposure or don't trade**

#### 3.4 Cost Awareness
```
Total_Cost = Spread + Commission + Market_Impact + Slippage

Signal must satisfy:
  Expected_Profit > 2-3x × Total_Cost
```

#### 3.5 Continuous Learning
```
if (model_degradation_detected):
  if (retrainable):
    trigger_retraining_pipeline()
  else:
    reduce_model_weight()
    escalate_to_human()
```

### 4. What The System Can and Cannot Do

**✅ CAN:**
- Detect market regime changes
- Avoid bad trading conditions
- Reduce drawdowns through risk management
- Adapt position sizing dynamically
- Process multimodal data at scale
- Provide explainable predictions
- Support human decision-making

**❌ CANNOT:**
- Guarantee profits
- Permanently outperform markets (alpha decays)
- Operate safely without human oversight
- Predict black swans
- Be regime-agnostic
- Eliminate all risk

## Complete Agent Specifications

### TIER 1: Data Ingestion (Building Raw R)

#### ✅ Agent 1: Feed & Data Ingestion Agent

**Purpose**: Fetch news and market data from external sources

**Inputs**:
- RSS feed URLs
- API endpoints (News API, Alpha Vantage, SEC EDGAR)
- Fetch intervals (configured)

**Processing**:
1. Parse RSS feeds using `feedparser`
2. Call REST APIs with rate limiting
3. Extract: title, content, published_at, source, url
4. Calculate content_hash (SHA-256)
5. Store in `raw_news` table

**Outputs**:
- `raw_news` table records

**Key Features**:
- Rate limiting (max 10 requests/minute per source)
- Retry logic with exponential backoff (3 attempts)
- Politeness policies (robots.txt compliance)
- Error handling for failed requests

**Configuration**:
```python
SOURCES = [
    {"type": "rss", "url": "https://feeds.reuters.com/reuters/businessNews"},
    {"type": "api", "name": "newsapi", "endpoint": "..."},
    {"type": "api", "name": "alphavantage", "endpoint": "..."}
]
FETCH_INTERVAL = 300  # seconds
```

**Status**: ✅ Implemented (22.01.2026)

---

#### ✅ Agent 1.5: Data Quality Agent

**Purpose**: Validate and score incoming data quality

**Inputs**:
- `raw_news` records

**Processing**:
1. **Duplicate Detection**:
   - Check content_hash against existing records
   - Fuzzy matching using embedding similarity (cosine > 0.95)
2. **Content Validation**:
   - Minimum word count (>100 words)
   - Language detection (must be English)
   - Structure check (has title AND content)
3. **Source Reliability**:
   - Lookup source in reliability table
   - Historical accuracy score
4. **Quality Score Calculation**:
   ```python
   quality_score = (
       0.3 * structure_valid +
       0.2 * length_adequate +
       0.2 * source_reliability +
       0.15 * language_correct +
       0.15 * (1 - is_duplicate)
   )
   ```

**Outputs**:
- `data_quality_scores` table records
- Flag: `is_duplicate`, `duplicate_of`, `validation_flags`

**Key Features**:
- SHA-256 content hashing
- Embedding-based fuzzy duplicate detection
- Language detection using `langdetect`
- Source reliability tracking

**Status**: ✅ Implemented (22.01.2026)

### TIER 2: Understanding (Building E - Narratives)

#### ✅ Agent 2: Content Understanding (NLP/LLM)

**Purpose**: Extract structured understanding from raw text

**Inputs**:
- `raw_news` records (passed quality check)

**Processing (using Claude/OpenAI API)**:
1. **Text Summarization**:
   - Short summary (1-2 sentences)
   - Medium summary (3-5 sentences)
2. **Key Fact Extraction**:
   - List of 5-10 key facts
   - Structured as JSON
3. **Sentiment Analysis**:
   - Overall sentiment (-1 to +1)
   - Aspect-based sentiment (per topic)
4. **Event Type Classification**:
   - Multi-label: Earnings, M&A, Regulation, Macro, Crisis, Product, Personnel, Legal
5. **Embedding Generation**:
   - 768-dim vector (OpenAI `text-embedding-ada-002` or sentence-transformers)

**Outputs**:
- `processed_news` table:
  - summary_short, summary_medium
  - key_facts (JSON array)
  - sentiment (float)
  - event_type (array)
  - embedding (vector)

**Prompt Template Example**:
```
Analyze this financial news article:

Title: {title}
Content: {content}

Provide:
1. Short summary (1-2 sentences)
2. Key facts (bulleted list)
3. Sentiment (-1 to +1)
4. Event type (Earnings/M&A/Regulation/etc.)
5. Affected entities (companies, sectors)
```

**Key Features**:
- Temperature=0.1 for consistency
- Token usage tracking
- Cost optimization (batching)
- Error handling for API failures

**Status**: ✅ Implemented (22.01.2026)

#### ✅ Agent 2.5: Fact Verification Agent

**Purpose**: Verify claims and detect contradictions

**Inputs**:
- `processed_news` records (key_facts)

**Processing**:
1. **Claim Verification**:
   - For each key fact, ask LLM: "Is this claim plausible given the context?"
   - Check for internal contradictions
2. **Cross-Reference**:
   - Compare facts against article content
   - Detect unsupported claims
3. **Credibility Scoring**:
   ```python
   credibility_score = (
       0.4 * internal_consistency +
       0.3 * contextual_support +
       0.3 * plausibility
   )
   ```

**Outputs**:
- `fact_verifications` table:
  - fact_id, news_id
  - claim (text)

#### ✅ Agent 4: Impact & Relevance Scoring Agent

```python
Impact = (

    RegimeSensitivity ×
    SectorSensitivity ×
    HistoricalReaction ×

)
```

**Component Definitions**:
1. **NewsImportance** (0-1):

6. **LiquidityAdjustment** (0.5-1.2):
   - Low liquidity (small cap): 1.2× (bigger moves)

**Outputs**:

#### ✅ Agent 5.5: Signal Decay Modeling Agent

**Purpose**: Model how news impact decays over time

**Inputs**:

   - M&A: 14 days (medium-lived)
   - Regulation: 60 days (long-lived)
   - Macro: 30 days
   - Crisis: 7 days (fast decay after peak panic)
3. **Current Strength Calculation**:
   ```python
   time_elapsed = now - event_timestamp
   current_strength = initial_impact × exp(-λ × time_elapsed)
   ```
4. **Signal Validity**:
   - If current_strength < 5% of initial: mark as "expired"

**Outputs**:
- `signal_decay_models` table:
  - news_id, entity_id
  - half_life (days)
  - decay_lambda
  - current_strength
  - is_expired

**Alternative Model**: Power-law decay (for events with long tails)
```python
strength(t) = initial_impact / (1 + t)^α
```

#### ✅ Agent 6.5: Confidence Calibration Agent

**Purpose**: Adjust model confidence to match historical accuracy

**Problem**: Raw ML confidence scores are often miscalibrated:
- Model says 80% confidence → only 60% accurate historically

**Inputs**:
- `predictions` (with raw confidence)
- `prediction_outcomes` (actual results)

**Processing**:
1. **Binned Calibration**:
   - Bin predictions by confidence: [0.5-0.6), [0.6-0.7), ..., [0.9-1.0]
   - For each bin, calculate actual accuracy
   - Create calibration curve
2. **Expected Calibration Error (ECE)**:
   ```python
   ECE = Σ (|confidence - accuracy|) × bin_weight
   ```
3. **Calibration Methods**:
   - **Platt Scaling**: Logistic regression on raw scores
   - **Isotonic Regression**: Non-parametric monotonic mapping
   - **Temperature Scaling**: Neural network output adjustment
4. **Apply Calibration**:
   ```python
   calibrated_confidence = calibration_function(raw_confidence)
   ```

**Outputs**:
- `predictions` table (update):
  - calibrated_confidence

**Monitoring**:
- Track calibration drift over time
- Alert if ECE > 0.15 (poorly calibrated)

#### ✅ Agent 7: Meta-Strategy Agent

**Purpose**: Intelligently combine multiple models into ensemble prediction

**Inputs**:

**Processing**:
1. **Model Performance Tracking**:

   ```python
   expected_return = Σ (weight_i × return_i)
   ```

5. **Confidence Aggregation**:

   ```python
   disagreement = std_dev(model_returns)
   confidence = base_confidence × (1 - disagreement_penalty)
   ```

**Outputs**:

### Key Schema Decisions

**TimescaleDB**:
- `market_data` table uses TimescaleDB hypertable for efficient time-series queries
- Automatic partitioning by time
- Compression for old data

**JSONB Columns**:
- `metadata` (JSONB): Flexible storage for varying data
- `audit_trail.context` (JSONB): Full decision context
- `predictions.direction_probabilities` (JSONB): Probabilistic outputs

**Indexes**:
- `raw_news.content_hash` (unique) - Duplicate detection
- `processed_news.embedding` (vector index) - Similarity search
- `predictions.timestamp, entity` (composite) - Time-series queries

**Foreign Keys**:
- Strict referential integrity
- Cascading deletes where appropriate
- Prevents orphaned records

## Glossary

**E (Expected World)**: Model-derived expectation of market state based on news, sentiment, fundamentals

**R (Reality)**: Actual observed market state (prices, volume, volatility)

**Δ (Delta/Divergence)**: Difference between E and R, used to identify opportunities and risks

**Regime**: Market condition category (volatility, trend, risk appetite, liquidity) that affects strategy behavior

**Alpha**: Return uncorrelated with market exposure (excess return)

**Beta**: Return from systematic market exposure

**Sharpe Ratio**: (Return - RiskFreeRate) / Volatility - risk-adjusted return metric

**VaR (Value at Risk)**: Maximum expected loss at given confidence level (e.g., 95%)

**CVaR (Conditional VaR)**: Expected loss given loss exceeds VaR (tail risk)

**Calibration**: Alignment between predicted confidence and actual accuracy

**ECE (Expected Calibration Error)**: Measure of calibration quality

**SHAP**: Method to explain ML model predictions via feature importance

**HHI (Herfindahl-Hirschman Index)**: Portfolio concentration metric

**PSI (Population Stability Index)**: Feature drift detection metric

**Kelly Criterion**: Optimal position sizing formula based on edge and odds

## Appendix: Architecture Patterns

### Multi-Agent Orchestration Pattern

```python
class AgentOrchestrator:
    """Coordinates agent execution with dependency management"""
    
    def __init__(self):
        self.agents = self._register_agents()
        self.dependency_graph = self._build_dag()
    
    def run_pipeline(self, trigger_event):
        """Execute agents in topological order"""
        execution_order = self._topological_sort(self.dependency_graph)
        
        for agent in execution_order:
            try:
                result = agent.run()
                self._store_result(agent, result)
            except Exception as e:
                self._handle_error(agent, e)
                if agent.is_critical:
                    raise
```

### Feedback Loop Pattern

```python
class FeedbackLoop:
    """Continuous learning from outcomes"""
    
    def __init__(self, prediction_agent, learning_agent):
        self.prediction_agent = prediction_agent
        self.learning_agent = learning_agent
    
    def update(self):
        """Daily feedback cycle"""
        # 1. Collect outcomes from yesterday
        outcomes = self.learning_agent.collect_outcomes()
        
        # 2. Calculate performance metrics
        metrics = self.learning_agent.calculate_metrics(outcomes)
        
        # 3. Detect degradation
        if self.learning_agent.detect_degradation(metrics):
            # 4. Trigger retraining or reduce weight
            if metrics.accuracy < 0.5:
                self.prediction_agent.retrain()
            else:
                self.prediction_agent.reduce_weight(0.5)
```

### Human-in-the-Loop Pattern

```python
class HumanController:
    """Provides override and supervision"""
    
    def __init__(self, orchestrator):
        self.orchestrator = orchestrator
        self.kill_switch_active = False
    
    def kill_switch(self):
        """Emergency shutdown"""
        self.kill_switch_active = True
        self.orchestrator.halt_all_agents()
        self.alert_operators(priority="CRITICAL")
    
    def override_regime(self, regime):
        """Manual regime classification"""
        self.orchestrator.set_regime(regime, source="human")
    
    def approve_trade(self, trade):
        """Manual approval for large/risky trades"""
        if trade.risk_score > 0.8 or trade.size > 0.10:
            return self.request_human_approval(trade)
        return True
```
